# Data contract

The single most important rule: **system files are auto-updatable; user files
are never touched by an update.** This is enforced by `internal/doctor` and by
tests over the update manifest.

## System layer (auto-updatable)

| Path | Purpose |
|---|---|
| `AGENTS.md`, `SKILL.md`, `DATA_CONTRACT.md`, `README.md` | The contract and router |
| `modes/*.md` | Judgment prompts. `_`-prefixed files are shared, not routable |
| `cmd/`, `internal/` | Go source: commands and deterministic cores |
| `content/uplanner.json` | Generated: 179 programs, 63 hiring reports |
| `content/resources.json` | Generated: free learning resources from Intersections |
| `content/roles.json` | Generated: role library (reality, screens, evidence, gaps) |
| `content/manifest.json` | Generated: counts, source paths, generation date |

`content/*.json` is generated by `go run ./cmd/gen-data`. Never edit it by hand.

## User layer (never auto-updated)

| Path | Purpose |
|---|---|
| `profile.yml` | Structured profile: education, experience, scores, targets, language |
| `resume.md` | The user's CV in Markdown, source-annotated |
| `evidence.md` | Source-backed fact store; the only place claims may come from |
| `data/applications.md` | Canonical application tracker (status, deadline, target, docs) |
| `data/learning.md` | Learning progress: resource id → state and notes |
| `data/fit/*.md` | Pasted job descriptions and their evaluations |
| `data/reports/*.md` | Generated reports — review artifacts, human-readable |
| `modes/_profile.md` | User archetypes, narrative, preferences |
| `modes/_custom.md` | House rules; procedural only, never a claim source |
| `.env` | Optional API keys, gitignored, never read by generators |

## Canonical vs derived

Human-readable Markdown and YAML files are canonical. Any index, cache or
derived JSON under the data root is disposable and rebuilt. A database will
never become a second source of truth.

## Concurrency

User-layer writes use an atomic temp-write + fsync + rename. Reports claim a
monotonic number before being written. Report numbers are never reused.

## Portability

The binary accepts `UPLANNER_DATA_DIR` so a user can keep their data outside
the install directory. A self-update must never write to that directory.
